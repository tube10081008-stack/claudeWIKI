## 0. Recap & 전환점

- **1~3강(RAG):** 모두가 똑같은 사전학습 모델(예: Gemma 4)을 두고, 그때그때 **외부 지식을 검색·주입**해 생성.
  → 핵심 고민은 "토큰/컨텍스트를 어떻게 효율적으로 가져올까".
- **4강(파인튜닝):** 이제는 **인공지능 모델 자체를 학습**시킨다. = 나만의 Gemma 4를 만든다.
  → 학습한 모델을 LM Studio/Ollama에 올리면, 일반 Gemma 4가 아닌 **커스텀된 나만의 모델**을 연결할 수 있다.

## 1. 미래 예상: 2027년 이후의 RAG

| # | 흐름 | 의미 |
| --- | --- | --- |
| 1 | **Knowledge Runtime (지식 실행 환경)** | RAG가 단순 라이브러리가 아니라, 기업 지식을 관리·검증하는 독립 **'운영체제' 레이어**가 됨 |
| 2 | **Real-time Autonomous RAG** | 데이터 생성 즉시 벡터/그래프 DB 반영, 에이전트가 사람 개입 없이 지식의 모순을 **스스로 해결(Self-healing)** |
| 3 | **SLM + RAG** | 거대 GPT-5/6 대신, 기업 온프레미스에 특화된 **초경량 모델 + 강력한 RAG**가 주류 (보안·비용 해결) |

> ⭐ 이 중 **3번(SLM + RAG)**이 핵심. 작은 모델(Gemma 4 E2B 등)에 RAG를 잘 결합 + **LoRA 파인튜닝**으로
> 기업 특화 두뇌를 만드는 것이 다음 세대 1인 기업의 무기.

## 2. 💼 여기서 만들 수 있는 비즈니스 5가지

> 어떤 테크가 정착될 때까지(약 2년) 그 과정을 **도와주는 스타트업**들이 크게 성장한다.

1. **로컬 LLM으로 돌아가는 자동화 에이전트** — 외부와 격리된 나만의/기업의 에이전트 구축 (컨설팅+개발)
2. **내 두뇌를 파인튜닝해 기업에 판매** — 특화된 '두뇌'만 만들어 파는 형태
3. **Physical AI 스타트업** — 로봇 안에 들어갈 경량 SLM (에너지 적게 → 배터리 오래)
4. **On-device AI 스타트업** — 스마트폰·소형기기에서 동작하는 AI
5. **타 기업 맞춤형 로컬 LLM 구축 스타트업** — RAG(브레인 인젝션)+파인튜닝+컨설팅 통합 제공

> 💡 자동화 에이전트 구축이 어려운 이유 = **인공지능 지식 + 바이브 코딩 + 사업 능력** 3가지를 다 갖춘 사람이 드물어서.
> → 개발자만의 영역이 아니다. 누구나 진입 가능한 스타트업.
> **실행 팁:** 만들고 싶은 아이디어를 바이브 코딩으로 웹사이트화 → K-Startup 정부 과제(예비창업/재창업/중장년 패키지) 지원.

## 3. RAG vs 파인튜닝 — 핵심 차이 (가장 중요)

> 비유: 책상 위에 소설·마케팅·수학 책 3권이 있고, 내 머리는 그 내용을 모르는 일반 모델.

| | **RAG (오픈북)** | **파인튜닝 (두뇌 변경)** |
| --- | --- | --- |
| 방식 | 필요할 때 책을 **검색해 가져와** 답함 | 책을 **보고 배워** 두뇌 자체가 바뀜 |
| 모델 | 그대로 (Gemma 4 유지) | 모델 내부가 변경됨 |
| 새 지식 | 즉시 추가·검색 가능 (매우 빠름) | 학습이 필요(느림), 대신 학습되면 안 봐도 됨 |
| 매 질문 | 매번 검색·로딩 반복 | 이미 내재화 |

> 🪪 비유: 캘리포니아 면허증을 처음 보면(RAG) 그때그때 찾아 읽지만, 사람은 보고 배우면(파인튜닝)
> 다음엔 안 봐도 안다. 두뇌의 뉴런 연결(전기 신호)이 바뀌는 것 = **파인튜닝**.

→ 둘은 **대체가 아니라 보완**. RAG로 지식을 연결하면서, 파인튜닝으로 두뇌를 특화한다.

## 4. AI 학습의 원리

### 인공지능 = 예측 모델
- "난 널 사랑해"에 "나도 널 사랑해"라고 답하면 **좋은 예측**. 이미지를 보고 "커피"라 하면 좋은 예측.
- **수많은 데이터**("이건 커피야" × N)로 학습해 예측을 잘하게 만든다.

### Overfitting(과적합) vs Underfitting(과소적합)
| | Overfitting (꼰대) | Underfitting |
| --- | --- | --- |
| 원인 | **너무 많이** 학습 | **너무 적게** 학습 |
| 증상 | 학습한 것만 완벽, 새 데이터엔 유연하지 못함 | 학습 데이터조차 제대로 인식 못 함 |

> 🏭 비유: 화장품 1000개를 완벽 인식하게 학습시켰더니, 새로 추가된 10개는 학습이 안 됨(꼰대화).
> → **적절한 학습량**을 찾는 '감'이 핵심. 이 **파라미터 조절 역량**이 곧 비즈니스 경쟁력.

### 가중치(Weight)와 LoRA
- 모델은 수학 모델: **y = w·x + b**. 여기서 **W(가중치)**가 정답을 맞추기 위한 숫자(0.1, 0.001…).
- **Full Fine-tuning:** W 전체를 다 바꿈 → 컴퓨팅 막대 → 구글/OpenAI 영역.
- **LoRA (Low-Rank Adaptation):** **끝의 작은 행렬만** 바꿈 → 저비용으로도 충분한 성능.
  - Linear Regression 비유: 선을 바꾸는 여러 방법 중 **맨 끝 값(위아래만 움직임)**만 조정 → 계산 적음.
  - 실습에서 전체 파라미터 중 **약 0.29%만** 학습해도 잘 됨을 확인 → 이게 LoRA 논문의 핵심.

## 5. 🛠️ 실습: Unsloth로 Gemma 4 파인튜닝 (Colab 무료)

> 도구: **Unsloth** — 무료/최적화된 학습 오픈소스. (저사양·무료 환경에서도 학습 가능하게 해줌)
> 모델: `unsloth/gemma-4 (E2B)` — Hugging Face보다 빠르게 쓰도록 변환된 버전.

### 핵심 설정 5가지
| 설정 | 의미 |
| --- | --- |
| **model name** | 사용할 모델 (예: `unsloth/gemma-4-E2B`) |
| **max_sequence_length** | 한 번에 생성할 토큰 수 (예: 1024, 클수록 비용↑) |
| **load_in_4bit** | True면 [양자화](../../concepts/quantization.md) (압축·고속) |
| **full_finetuning** | True=두뇌 전체 변경 / False=LoRA(일부만) |
| (추론) **temperature / top_p / top_k** | 생성 방식 제어 (이전 강의) |

### 학습 흐름
1. **학습 전 베이스라인 테스트** — "내가 만들고 싶은 사업 질문"을 던져 모델이 모르는지 확인 (예: "OO병원 OO환자 정보?" → 모름).
2. **데이터 만들기 (가장 중요)** — Hugging Face 표준 형식(`role`: user/assistant, JSON)으로 **질문-답변 모범답안**을 다량 생성.
   - 예: "초록초록 호텔 주방장은?" → "초록뽕입니다. 스팸구이를 잘하지요." (= 일반 모델엔 없는 나만의 데이터)
   - 30개는 부족, **100~1000개+** 필요. **AI로 생성**하는 게 효율적(손으로 X).
3. **chat template 적용** — 데이터에 turn 토큰을 붙여 모델이 알아듣는 형식으로 변환.
4. **학습 파라미터 조절** — 직접 실험하며 찾는다:
   | 파라미터 | 의미 (비유) |
   | --- | --- |
   | **learning_rate** | 학습 속도 (책 1권에 10초 vs 1년 주기) |
   | **max_steps** | 학습 횟수 (예: 30번 — 실험용. 제대로는 더 많이) |
   | **per_device_train_batch_size** | 유효 배치 크기 (한 번에 볼 샘플 양) |
5. **Loss(로스) 줄이기 = 목표** — 로스 = **정답값과 예측값의 차이**.
   - 매 스텝 오르내리지만 **평균적으로 감소**해야 잘 학습되는 것.
   - ⚠️ 30번은 턱없이 부족 / 너무 많으면 Overfitting → **적절점**을 실험으로 찾기.
6. **추가 학습(resume)** — 처음부터가 아니라 기존 체크포인트에서 스텝을 더 얹어 이어 학습 가능.
7. **`.py` 다운로드 → 안티그래비티에서 분석** — 코드를 받아 AI와 함께 개선.
