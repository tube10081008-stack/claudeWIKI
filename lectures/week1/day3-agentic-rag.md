# Week 1 · Day 3 — Agentic RAG: 추론(Reasoning)과 자율성을 정복하다

> **단계:** Step 1 (RAG) · 3주차 — 2026년 현재: Agentic & Modular RAG
> **주제:** RAG에 **추론(Reasoning)**과 **자율성(Autonomy)**을 더한 최전선
> **기반 논문:** Two-world Agentic RAG with deep reasoning (HKUST·Illinois·UCLA·Tokyo 등 7개 대학),
> Medical Graph RAG (의료 분야 할루시네이션 해결)

## 0. 명심: 우리는 소비자가 아니라 생산자다

| | |
| --- | --- |
| **소비자** | "아우디 좋대! 벤츠 S클래스 나왔대!" — 남이 좋다니까 그냥 쓰는 사람 |
| **생산자** | 목적에 맞는 자동차를 **직접 만들어 파는** 사람 |

- 생산자는 **금액(비용)을 효율적으로** 쓴다. 대중용 차에 페라리 엔진(300km 엔진)을 넣지 않는다.
- 우리는 웹사이트·모바일앱·콘텐츠뿐 아니라 **AI 서비스·AI 모델·커넥트 AI 같은 도구**까지 만들어 팔 수 있어야 한다.
- 그래서 **원리**를 알아야 한다.

---

## 1. RAG의 진화: 지식 주입 → 추론 추가

LLM의 두 가지 치명적 약점:
1. **지식의 부재** — 사전학습(pretrained)이라 이미 옛날 데이터. 새 지식이 없다.
2. **논리의 붕괴** — 복잡하고 깊게 생각해야 하는 문제를 잘 못 푼다.

해결 흐름:
- **① 지식 주입 → RAG** (오픈북): 외부 지식으로 부족분을 채움.
- **② 추론 → Reasoning**: 복잡한 문제를 위해 **Chain of Thought**(생각의 사슬) 도입.
  - "이건 이래서 이렇고, 그건 그래서…" 단계별 사고 흐름을 따라가면 훨씬 잘 푼다.
- 이 둘이 결합하며 진화.

---

## 2. 핵심 전환: '먼저 생각하고, 그다음 검색한다'

- 문제 발견: **부정확한 검색이 추론을 오염**시킨다. (Self-RAG로도 부족)
- 그래서 **검색 → 생각**이 아니라 **생각 → 검색** 순서로 바꿈.
  - "어떤 키워드로 검색하면 좋을까?"를 먼저 고민. (똑똑한 사람이 검색 전략을 세우듯)

### 검색–통합–생성 추론 루프
```
복잡한 질문
   │  ① 작은 질문들로 쪼갠다 (decompose)
   ▼
각각 검색
   │  ② 가져온 많은 문서 중 진짜 필요한 것만 쏙쏙 뽑아 재조합
   ▼
필터링 + Self-RAG 반성
   │  ③ 다시 한번 검증하며 생성
   ▼
답변
```

> 어렵게 생각할 필요 없다. **"사람이 똑똑하게 생각·검색하는 과정"**을 그대로 흉내 낸 것.

## 3. 복잡도 폭발 → Agent Orchestration

검색·추론·도구(DB, 실시간 검색, 외부 도구)를 다 넣으니 **너무 복잡**해졌다.
- 글·이미지·음악까지 생성하는 **멀티모달** 확장 → 하나의 에이전트로 감당 불가.
- → **에이전트 오케스트레이션**: 여러 에이전트를 지휘자처럼 조율.

### 추론(Reasoning) 구조 3종
| 구조 | 설명 |
| --- | --- |
| **Chain-based** | 한 줄로 추론: 컵→흰색→페인트→공장→노동자… (단순한 문제) |
| **Tree-based** | 마인드맵처럼 하나에서 여러 갈래로 분기 (중간 복잡도) |
| **Graph-based** | 모든 지식을 펼쳐 패턴 추출 (매우 복잡한 문제: 자동차/세계 등) |

### 강화학습 (Reinforcement Learning)
- **Exploration(탐험)**: 아기처럼 아무거나 시도 → 틀리면 배움 → 점점 똑똑해짐.
- 단일 에이전트를 그냥 던져놓고, 무식하게 컴퓨팅을 넣어 **더 좋은 답이 나올 때까지** 반복.

### 멀티 에이전트 협업 구조
| 구조 | 특징 |
| --- | --- |
| **Centralized (수직적)** | CEO→부장→과장… 지휘자(CEO)가 명령 배분 |
| **Decentralized (수평적)** | 중앙이 없음. 모두가 평평하게 협업 |

> ⚠️ **2026년 = 혼란(Chaos)의 시기.** 논문들도 "그냥 다 써보는 단계"다.
> 이 혼란(=문제점)을 직접 느껴야 다음 단계로 성장한다. ChatGPT/Gemini만 써본 사람은 이 고통을 모른다.

## 4. Hugging Face — AI계의 GitHub

- GitHub = 개발자 공유 공간 / **Hugging Face = AI 개발자 공유 공간** (모델·데이터·Spaces).
- **약 258만 개**의 인공지능 모델이 대부분 **무료**로 공개되어 있다.
- (전망) 지금은 무료지만 2~3년 뒤 성과가 나오면, 큰 기업부터 유료화될 것 → 지금 빨리 배워야 함.

### Task(기능)별 6대 분류
| 분류 | 설명 |
| --- | --- |
| Multimodal | 여러 형식을 한 번에 |
| Computer Vision | 이미지 생성/분류 |
| NLP | 글(텍스트) 생성 |
| Audio | 음악·음성 생성 |
| Tabular | 엑셀/표 데이터 |
| Reinforcement Learning | 강화학습 |

### 정렬(Sort) 기준
Trending(핫함) · Most likes · Most downloads · Recently created · Recently updated ·
**Most parameters**(복잡·고성능, 컴퓨팅 多) · **Least parameters**(가벼움, 스마트폰 가능. 예: Gemma 2B)

### 모델 선택 = 자동차 엔진 고르기
- 에이전트마다 **다른 두뇌**를 써야 한다. (글 쓰는 Leo ≠ 음악 만드는 Luna ≠ 이미지 만드는 Designer)
- **멀티모달 하나로 다 처리**하면 편하지만 **컴퓨테이션을 과하게** 잡아먹는다.
  - 유튜브 관리 에이전트에 Computer Vision 모델만 넣으면, 정작 핵심인 텍스트 분석을 못 한다.
- 60km만 가면 되는 차에 페라리 엔진을 넣지 마라 → **목적에 맞는 적절한 모델 + 컴퓨테이션 효율**.

## 5. 클라우드 vs 로컬 LLM

| | 클라우드 API (OpenAI/Gemini) | 로컬 LLM |
| --- | --- | --- |
| 보안 | ❌ 외부 통과 | ✅ 100% 내부 보관 |
| 비용 | 쓸 때마다 과금 | 초기 하드웨어 구축 후 무료 |
| 커스터마이징 | ❌ 준 대로만 | ✅ 가능 (파인튜닝) |
| 인터넷 | 필수 | 불필요(단절 가능) |
| 단점 | 가격·성능 변동성 | 좋은 GPU/RAM 필요 |

### 모델 커스터마이징 3단계
| 방법 | 설명 |
| --- | --- |
| **Pretraining (사전훈련)** | 모델을 처음부터 학습. 컴퓨팅 막대 → 우리가 하긴 어려움 (구글/OpenAI 영역) |
| **Fine-tuning (미세조정)** | 기존 모델을 조금 수정 (예: 특정 강아지를 더 잘 인식하게 사진 1000장 학습) |
| **LoRA** | 가벼운 비법노트만 얹어 즉각 실력 향상. RAG와 유사한 결 |

### 양자화 (Quantization)
- 너무 큰 모델을 다 못 쓰니, **지능은 거의 유지하며 크기를 압축**하는 기술(양자화).
- 컴퓨터 사양이 낮아도 모델을 돌릴 수 있게 해준다. (단계가 높을수록 빠르지만 지능 약간 하락)

### 실행 도구
| 도구 | 특징 |
| --- | --- |
| **Hugging Face** | 모델 앱스토어 (모아놓는 곳) |
| **Ollama** | 터미널 중심, 더 빠름. 양자화 자동 |
| **LM Studio** | GUI(그래픽) 중심, 시각적으로 모델 관리 |
| **Connect AI** | 위 모델들을 안티그래비티에서 코딩·에이전트로 연결 |

## 6. 실습: 이미지 생성 로컬 모델 + Colab

- **Google Colab**: GPU(그래픽카드) 없는 사람이 클라우드 GPU로 AI를 돌리게 해주는 도구.
  - 뿌리는 **Jupyter Notebook**(연구자들이 코드 실험·공유하던 도구).
  - `런타임 유형 변경 → T4 GPU(무료)` 설정. (유료 컴퓨팅은 일단 사지 말 것)
- **흐름:** Hugging Face에서 `Use this model → Colab` → 코드 복붙 → 모델 다운로드 → 이미지 생성.
  - 큰 모델(10GB 등)은 무료 T4에서 실패할 수 있음 → **양자화 버전**이나 **Least parameters** 모델 사용.
- **로컬로 가져오기:** 모델 이름 코드를 복사 → 안티그래비티에 "이 로컬 모델 내 컴퓨터로 가져와 구현" 지시.

### 실습 모델 (3강 교재)
- 이미지 생성: `JSCPPProgrammer/z-anime-distill8-gradio-zerogpu` (애니메이션, 증류 모델)
  - 권장 설정: **Steps 8 / CFG 1.0~1.5 / Sampler Euler_a / Scheduler Beta / Denoise 1.0 / FP8**
  - ⚠️ Steps·CFG를 일반값(7.0+)으로 올리면 색상 붕괴(이미지 타버림) 발생.
- 음악 생성: `ACE-Step/acestep-v15-xl-turbo` (핫한 음악 생성 모델)

### 💰 라이선스: 사업화 가능 여부
- **Apache 2.0** = 수익화·상업적 사용 **모두 허용** (약 44만 개 모델, Gemma 4 포함).
- Hugging Face에서 라이선스로 필터링해 **상업 가능 모델만** 골라 만들어 팔 수 있다.

## 🔑 핵심 한 줄 정리

> **Agentic RAG = RAG + 추론 + 자율성.** "먼저 생각하고 검색"하며, 여러 에이전트를 오케스트레이션한다.
> 2026년은 혼란기 — 그 혼란을 직접 느끼고 풀어가는 과정이 곧 생산자의 경쟁력이다.
