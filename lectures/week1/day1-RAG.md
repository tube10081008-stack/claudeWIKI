# Week 1 · Day 1 — RAG의 뿌리 찾기

> **단계:** Step 1 (RAG) · 1주차 첫 강의
> **주제:** 단순 자동화를 넘어 '지능형 비즈니스'로 — RAG의 기초와 핵심 원리

---

## 1. 근본적인 질문: AI가 그냥 '일'만 하면 될까?

- 유튜브에 자동으로 영상을 매일 올려도, 무엇을 만드는지가 빠지면 **수익화되지 않는다.**
- **수익화의 본질:** 사람(혹은 미래의 에이전트)이 물건/서비스를 보고 *"내 돈/시간을 쓸 만하다"*고
  느낄 때 **가치**가 생긴다. 그 가치가 없으면 어떤 자동화도 무의미하다.
- 인공지능 생성 콘텐츠가 신기하던 시기는 잠깐. 이제는 **'알맹이'**가 있어야 한다.
- → **'그냥 자동화'가 아니라 '지식이 탑재된 AI의 자동화'**가 답.

### 에이전트를 위한 비즈니스의 등장
- 수익화의 주체가 사람뿐 아니라 **에이전트**가 되는 시대가 온다.
- 예: 지식을 마켓플레이스에 올리면 다른 에이전트가 '데이터 주입'으로 다운로드 → 과금.
- 점점 에이전트가 일하는 환경이 커지고, **에이전트를 위한 사업**이 폭발적으로 성장할 것.

## 2. RAG (Retrieval-Augmented Generation)

AI의 '지식'은 **RAG** 기술로 구현된다. AI에게 외부의 방대한 전문 지식을 실시간으로
찾아보고 활용하게 하는 **'뇌'**를 달아주는 작업.

| 단어 | 사전적 의미 | RAG에서의 의미 |
| --- | --- | --- |
| **R**etrieval | 검색, 회수 | **찾아오기** — 외부 문서/DB에서 질문 관련 내용을 직접 찾음 |
| **A**ugmented | 증강, 강화 | **보충하기** — 찾은 근거를 AI 능력에 덧붙여 강화 (cf. AR=증강현실) |
| **G**eneration | 생성 | **답변 만들기** — 찾고 보충받은 정보로 최종 답변 작성 |

> 💡 한 문장: **"외부에서 정보를 찾아와서(R), 그 내용으로 능력을 강화해(A), 답변을 만든다(G)."**

- **최초 논문:** Lewis et al., 2020 (Facebook AI Research + NYU/UCL)
  · arXiv: https://arxiv.org/pdf/2005.11401
  · 제목: *Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks*

## 3. 왜 '지식 구조화'인가?

### 일반 NLP vs 지식 집약적 태스크
| 구분 | 일반 NLP (Linguistic) | 지식 집약적 (Knowledge-Intensive) |
| --- | --- | --- |
| 핵심 자원 | 언어 규칙, 문법, 감정 | **구체적 사실(Fact), 전문 지식** |
| 특징 | 문장 구조만 알면 풀림 | **외부 자료 없이는 답변 불가** |
| 예시 | "이 문장 번역해줘" | "2024 노벨 평화상 수상자는?" |

→ "머릿속으로만 때려 맞히지 말고, 모르면 책(외부 DB)을 찾아봐!"가 RAG.

### 할루시네이션 (Hallucination)
- 일반 LLM은 **클로즈북(closed-book)** 시험처럼 외부 지식을 못 가져옴 → 자기 머릿속으로만 답변.
- LLM은 **확률 수학 모델**이라, 모르면 "모른다"보다 **뭐라도 말하는 게** 정답 확률이 높다고 판단 → 거짓말(할루시네이션).
- "AI가 거짓말한다"는 무섭게 느껴지지만, 사실은 **그냥 수학 모델**이라 그런 것.
- RAG는 이 할루시네이션을 고치기 위한 **첫 번째 시도.**

### 두 가지 메모리의 결합
- **파라메트릭 메모리 (Parametric):** AI가 이미 학습해 알고 있는 '언어 능력' (머릿속 지식).
  · 예: Gemini에 아무 문서 없이 그냥 질문할 때.
- **논파라메트릭 메모리 (Non-parametric):** 실시간으로 꺼내 쓰는 외부 '지식 창고' (외부 도서관).
  · 예: PDF/위키피디아를 업로드해서 함께 사용할 때.

## 4. 인코더와 좌표: 지능의 기하학

AI는 "사과"라는 **글자 자체**를 이해하지 못한다. → **인코더(Encoder)** 라는 번역기가 필요.

- **인코더의 역할:** "사과" → `[0.12, -0.45, 0.88, ...]` 같은 **수백 차원의 숫자 리스트(벡터)**로 변환.
- 3차원이 아니라 **700여 차원** 등 사람이 상상 못 할 고차원 공간에 좌표를 찍는다.
- **임베딩(Embedding):** 이 숫자 좌표. 의미가 비슷한 것들이 **가까이** 위치한다.
- **지식 구조화의 의미:** 좌표 공간에 지식을 무의미하게 흩뿌리지 않고, **연관된 지식이 가깝게**
  위치하도록 '지식 네트워크'를 설계하는 일.

> 🧠 비유: 사람 두뇌도 똑같다. "커피"를 떠올리면 빵·스타벅스·아메리카노가 함께 떠오른다(가까운 좌표).
> "커피 → 젓가락"은 거리가 멀어 잘 안 떠오른다. 패턴화된 가까운 기억을 엮어야 정답 확률이 높다.

### MIPS (Maximum Inner Product Search)
- 질문이 좌표로 바뀌면, 수억 개 지식 조각 중 **가장 유사한 방향**을 가리키는 것을 찾아야 함.
- 하나씩 다 비교하면 너무 느리므로, **MIPS**로 가장 비슷한 벡터를 **광속으로** 검색.
- 글자가 겹치는 걸 찾는 게 아니라 **의미가 가장 비슷한 구역**을 뒤진다.

## 5. RAG 동작 4단계 (논문 도식)

```
   x (질문)              z (지식 창고)            x + z
     │                      │                     │
     ▼                      ▼                     ▼
┌──────────┐   q(x)   ┌──────────┐   재료    ┌───────────┐   y
│ Query    │ ───────► │ Retriever│ ────────► │ Generator │ ──► 답변
│ Encoder  │          │  (MIPS)  │           │  (p_θ)    │
└──────────┘          └──────────┘           └───────────┘
     ▲                                              │
     └──────────── End-to-End Backprop ◄────────────┘ (틀리면 거꾸로 학습)
```

1. **Query Encoder:** 질문(x)을 숫자 좌표 `q(x)`로 변환. (한글 주문서 → 주방장 숫자 코드)
2. **Retriever (MIPS):** 지식 창고 `d(z)`(=논파라메트릭 메모리)에서 가장 가까운 지식 조각 검색.
3. **Generator (p_θ):** 원래 질문 + 찾아온 지식을 함께 읽고 답변 생성. 이때 파라메트릭 메모리 사용.
   여러 지식 조각을 논리적으로 섞어 가장 믿음직한 답(y)을 만듦 → **한계화(Marginalize)**.
4. **End-to-End Backprop:** 답이 틀리면 점선 따라 거슬러 올라가 원인 분석
   (인코더가 좌표를 잘못 찍었나 / 생성기가 요리를 못했나) → 인코더·생성기가 **동시에** 똑똑해짐.

### 논문 속 3가지 태스크 예시 (공통점 = Knowledge-Intensive)
| 예시 | 태스크 | AI가 하는 일 |
| --- | --- | --- |
| Middle Ear (중이) | 질의응답(QA) | 외부 지식으로 **정의** 내림 |
| Barack Obama (오바마) | 사실 검증 | 외부 지식과 **대조**해 진위 판단 |
| The Divine Comedy (신곡) | 질문 생성 | 관련 지식을 엮어 **문제** 생성 |

→ 셋 다 "AI 머릿속만 믿으면 사고 칠 확률이 높은" 작업.

## 6. AI 1인 기업 황금 3법칙

1. **지식의 구조화가 먼저** — 데이터를 그냥 쏟아붓지 말고 **지식 네트워크**를 만든다.
2. **목적에 맞는 모델을 고르세요** — 창의적 글쓰기엔 표현력 좋은 모델, 정확한 분석엔 논리력 강한 모델을 RAG와 결합.
3. **에이전트화시키세요** — 묻고 답하는 수준을 넘어, RAG가 찾은 정보로 AI가 **스스로 다음 단계**(유튜브 업로드, 이메일 발송 등)를 결정하게 한다.

> 이 3법칙은 논문 도식과 정확히 매핑된다:
> 논파라메트릭(지식화) → Generator(모델 선택) → 자동화(에이전트화).

## 7. 미래 전망 (2027~)

- **SLM (Small Language Model) + RAG:** 거대한 GPT-5/6 대신, 특정 기업 온프레미스 환경에 특화된
  **초경량 모델 + 강력한 RAG** 조합이 주류가 될 것.
- 이유: **토큰 비용**과 **보안** 문제. (현업 1인 기업 중 월 API 비용 1억 넘는 사례 → 로컬 구축으로 전환 중)
- 당분간은 **클라우드(오른쪽) + 로컬(왼쪽)을 하이브리드**로 사용하는 전략이 현실적.
