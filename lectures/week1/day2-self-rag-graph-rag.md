# Week 1 · Day 2 — 진화의 시작: '의심'과 '연결'을 가르치다

> **단계:** Step 1 (RAG) · 2주차 — 고도화 테크닉 (2023~2024)
> **주제:** 문서만 주면 끝? AI에게 **의심(Critique)**과 **연결(Graph)**을 가르친다
> **기반 개념:** Self-RAG, Graph RAG (Microsoft Research)

---

## 0. 왜 RAG 내부 원리까지 공부하나?

- 커넥트 AI·오픈클로·헤르메스 같은 도구를 **그냥 쓰기만** 하면 **소비자**일 뿐이다.
- 우리는 **AI 1인 기업 = 생산자**다. 내부 구조를 이해해야 도구를 **만들고 팔 수** 있다.
- 원리와 코어를 알면 → 직접 비슷한 도구를 만들어 판매하는 등 **다양한 BM**이 열린다.

---

## 1. 문제: 'AI 슬롭(Slop) 2.0'

- 1강에서 할루시네이션을 고치려 RAG(검색)를 넣었더니, **새로운 슬롭**이 생겼다.
- **무지성 검색**: 그냥 아무거나 막 검색해서 가져오는 것 → 신뢰할 수 없는 쓰레기 지식이 쌓임.
- 에이전트가 24시간 자동으로 정보를 모으면, 그 정보의 **신뢰성**이 핵심 문제가 된다.
  - 비유: 신입사원 100명에게 "조사해 와"라고 시켰는데, 검증 없이 그대로 전략에 쓰면 사고 난다.
- → AI가 모은 지식을 **어떻게 신뢰할 것인가?** 두 갈래의 연구가 시작됨:
  1. **Critique(의심)** → Self-RAG
  2. **Connection(연결, 그래프)** → Graph RAG

---

## 2. Self-RAG — AI가 스스로 의심한다

**핵심:** 사람이 아니라 **AI 스스로(Self)**가 자기가 모은 지식을 다시 평가(Critique)하는 RAG.

### 배경: Critique의 뿌리 (GAN)
- 예전 GAN: **Generator(생성자)** vs **Discriminator(판단자)**가 서로 싸우며 더 좋은 모델을 만듦.
- Critique = **선생님 역할**. 미대 교수가 그림을 보고 "이건 쓰레기, 이건 좋아"라고 평가하듯,
  AI가 모은 지식을 평가해 좋은 것만 남긴다.

### 4가지 자가 평가 기준 (Reflection Tokens)
AI가 "혼잣말"로 스스로 검증하는 4단계:

| 순서 | 질문 (is~) | 의미 |
| --- | --- | --- |
| 1 | **isRetrieve** | 이거 검색이 필요한 내용인가? (이미 아는가 / 찾아야 하는가) |
| 2 | **isRelevant** | 검색해온 문서가 질문과 진짜 관련 있는가? |
| 3 | **isSupported** | 내 답변이 가져온 문서에 의해 뒷받침되는 팩트인가? |
| 4 | **isUseful** | 최종 답변이 사용자에게 진짜 쓸모 있는가? |

→ 통과하면 **저장·사용**, 통과 못 하면 **폐기**. 점수가 안 되면 아예 저장하지 않을 수도 있다.

### 왜 중요한가 (1인 기업 적용)
- 에이전트가 두뇌 폴더에 지식을 마구 쌓으면 → **쓸모없는 지식 = 시간·메모리·토큰·에너지 낭비**.
- 쓸데없는 내용을 DB에 넣지 않고, 검색 시 뒤지는 시간도 절약 → **퀄리티 컨트롤러**로 AI 슬롭 방지.
- 커넥트 AI의 **'자가 검증 켜기'** 기능이 이 Self-RAG. CEO 에이전트가 다 검증하면 과부하 →
  각 에이전트(유튜브/인스타 등)가 **1차 셀프 검증** 후 CEO가 **2차 검증**하는 계층 구조가 효율적.

## 3. Graph RAG — 점(點)이 아니라 선(線)으로 연결한다

**핵심:** 지식을 **점**으로 흩뿌리는 게 아니라 **선으로 연결한 그래프**로 만들어, 전체 맥락을 본다.
(Microsoft Research, *Global RAG approach*)

### Vector RAG의 한계
- 기존 [벡터 RAG](../../concepts/encoder-vector.md)는 **로컬(local)** 검색에 강하다.
  - 예: "삼성 스마트폰 출시 연도?"처럼 **정확한 키워드**를 주면 주변 벡터만 찾아 효율적.
- 하지만 "이 데이터셋의 **주요 트렌드**는?", "1만 권 읽고 핵심 3가지 요약" 같은
  **전역적(global)** 질문엔 약하다 → 결국 전부 다 읽어야 해서 비효율.

### 해결: 점 → 선 → 그래프
- 점들을 **선으로 연결**해 그래프를 만들고, 그 안의 **엔티티(특징)**와 **관계**를 추출.
- 나무가 아니라 **숲(전체 맥락)**을 본다.
- **마인드맵**과 유사: 하나의 주제에서 연관 키워드를 가지치며 연결.

### 핵심 메커니즘: 태그(Tag) 기반
- 검색의 기반이 **태그/키워드 분류·연결**이다.
- **YouTube 알고리즘**이 바로 Graph RAG 기반 → 영상 업로드 시 **태그**를 다는 이유.
  (해시태그처럼, 거대한 지식 노드 중 가장 적절한 걸 사용자에게 추천)

### Graph RAG 6단계 파이프라인
```
모든 소스 문서
   │  ① Chunking (청크로 잘게 나눔, 예: 600토큰/PDF 100장 → 100개 점)
   ▼
핵심 단어(엔티티) 추출
   │  ② Entity 추출
   ▼
지식 그래프 구축
   │  ③ 점들을 관계로 연결
   ▼
커뮤니티 감지 (Hierarchical Partitioning)
   │  ④ 계층적 분할: 루트 커뮤니티 → 서브 커뮤니티 → 세부
   ▼
커뮤니티별 요약
   │  ⑤
   ▼
Map-Reduce로 응답 생성 → 글로벌 답변(y)
      ⑥ 지도를 위주로 줄임 — 전체가 아닌 중요한 것만 추출
```

- **계층 비유:** 지구(루트) → 한국·미국·브라질(서브) → 강남구·인천(세부) … 점점 세부화.
- **Map-Reduce:** 모든 지도를 다 보는 게 아니라 그 안의 중요한 것만 추려 하나의 아웃풋 생성.

## 4. 실습 연결: 지식 네트워크 시각화

- 안티그래비티 / 옵시디언의 **'지식 네트워크 보기'**가 바로 이 그래프 구조.
- 두뇌 폴더의 점들이 어떻게 연결됐는지, **루트 커뮤니티 vs 서브 커뮤니티**를 직접 관찰.
- `raw` 폴더 = 내가 검색·주입한 지식 / `agent` 폴더 = 에이전트가 24시간 모은 지식.
- 사람마다 지식 네트워크 **모양이 다르다** → 패턴을 보며 "왜 이렇게 연결됐지?"를 탐구.

> 💬 도구(옵시디언이든 뭐든)는 중요하지 않다. **데이터를 어떻게 쌓고 연결하느냐**가 본질.
