# Week 2 · Day 7 (7강) — 자동화 에이전트의 근간: 멀티에이전트 이론과 구현

> **단계:** Step 2 (Agent) — 여러 에이전트가 지식을 공유하며 협업하는 '근간' 이론
> **주제:** 멀티에이전트의 핵심 = **지식 공유**. 단기기억(RAG)을 검증해 장기기억(파인튜닝)으로 통합한다.
> **기반 논문:** MetaGPT · AgentVerse/Generative Agents · Multi-Agent Debate(EoT)

---

## 0. 자동화 에이전트의 진짜 정체 = 멀티에이전트(Multi-Agent)

- "자동화 에이전트"는 유행어지만, 코어는 옛날부터 연구된 **멀티에이전트(Multi-Agent)** 연구.
  - 강화학습(알파고)의 핵심이 에이전트 → 여러 에이전트가 **어떻게 지식을 쌓고·공유하고·목표를 달성**할까.
- 일반 대화형 AI vs 에이전트: 에이전트는 **도구(tools)**까지 갖춘다.
- ⚠️ **핵심 문제:** 에이전트가 100·1000개로 늘면 더 똑똑해져야 하는데 **오히려 멍청해진다**
  (무한 채팅·잡소리만, 핵심 일을 못 함). 실제 기업 컨설팅 현장에서도 이게 가장 큰 미해결 과제.

> 💡 **집단지성 비유 — 영화 〈군체〉:** 멍청하던 좀비들이 **하나의 기억을 공유**하며 학습·진화.
> "마네킹은 사람이 아니다"를 한 마리가 깨달으면 전체가 즉시 학습. (개미 집단지성·아이로봇·웨스트월드와 같은 결)

---

## 1. 핵심 3대 지식 공유 패턴 (논문)

> 셋은 단계적 진화: ① 완성 지식 공유 → ② 환경으로 자동 전파 → ③ 추론 과정까지 공유.

### ① Shared Message Pool (블랙보드) — **MetaGPT** / AutoGen GroupChat
- 1:1 대화가 아니라 **가운데 공유 게시판(Blackboard)** 하나를 두고 일한다.
- **Publish-Subscribe:** 한 에이전트가 산출물을 게시판에 **발행** → 필요한 에이전트가 **구독**해 자기 지식 업데이트.
- **표준 운영 절차(SOP)**를 두고 모두 거기서 정보를 가져옴.
- 특징: 지식 중앙집중 → 100개로 늘어도 대화가 안 꼬이고 **Single Source of Truth** 공유. 토큰 소모도↓.
- 논문: https://arxiv.org/pdf/2308.00352

### ② Shared Environment & Memory — **AgentVerse** / Generative Agents
- 에이전트들을 **하나의 가상 데이터 공간(Environment)**에 함께 밀어 넣는다.
- A가 학습·행동 → 결과가 **공유 환경 DB**에 기록 → 다른 에이전트가 **관찰(Observation)**하다 "어? 바뀌었네" 하고 자동 흡수.
- 특징: **위키 문서를 여러 명이 동시 편집**하거나 소문이 퍼지는 과정과 유사.
  - (소문 비유: 사람끼리 전파하면 **로스/왜곡**·지연 발생 / 데이터 공유는 변질 없이 빠르게 동기화)
- 논문: https://arxiv.org/abs/2308.10848

### ③ Exchange of Thought (EoT) — **Multi-Agent Debate** / ChatEval
- 완성 지식이 아니라 **문제 해결의 추론 과정(컨텍스트) 자체**를 실시간 공유.
- A "내 생각엔 이게 맞아" → B "그 흐름에서 이 부분이 빠졌으니 보완" → 서로의 프롬프트 메모리를 엮음.
- 특징: 개별 에이전트의 편향·할루시네이션이 공유 과정에서 **필터링** → 혼자선 불가능한 **집단지성** 형성.
- 논문: https://arxiv.org/pdf/2308.07201

### 구현 로드맵 (강의자 정의)
- **Step 1**(오늘): Shared Message / SOP — **검증된 지식을 함께 만들기**
- **Step 2**: 모든 에이전트가 그 지식을 함께 갖기
- **Step 3**: 에이전트끼리 공유 지식을 평가·추론·개선 (= EoT)

## 2. 구현: 단기기억(RAG) → 장기기억(파인튜닝) 통합

> Connect AI / ezerai 도구의 '두뇌' = **단기기억(GitHub) + 장기기억(Hugging Face)**.
> ([단기 vs 장기 기억](../../concepts/short-vs-long-term-memory.md) 복습)

### 왜 단기/장기를 나누나
1. **지식이 많아지면**(매뉴얼 100권) 매번 다 읽는 건 너무 느림 → 중요한 건 장기기억으로 옮김.
2. **여러 에이전트**가 각자 단기기억만 들면 복잡·느림 → 적절히 **배치(batch)**로 모아 모델을 업데이트.

### J브레인 — 검증된 코어 지식
- 인간(전문가)이 직접 검증한 지식만 모은 GitHub 저장소(암호화).
- 샘플 28개를 카테고리 자동 분류: 마케팅·코딩·사업·일반.
- **임계점(critical mass):** 양질의 코어 지식을 먼저 갖추면(손흥민의 기본기처럼) 이후 지식이 들어와도 잘 확장.
  중구난방으로 막 쌓으면 오히려 멍청해진다.

### 단기 → 장기 학습 방법 2가지 (도구 버튼)
- **SFT (Supervised Fine-Tuning):** 주입식 교육. 단기 지식을 학습 데이터(Q&A)로 **변환 + 증강** → HF 업로드 → 자동 학습 노트북(Colab)에서 학습 → 모델 HF 업로드 → LM Studio/Connect AI에서 사용.
  - learning_rate 강도: **안전(많이 띄엄)· 기본(중간)· 강하게(한 장씩)** — 책 넘기는 비유.
- **AI 자동 피드백 (강화학습 기반):** AI가 좋은 답(+)/나쁜 답(−)을 스스로 만들어 품질을 학습.

## 3. 카테고리 분류 이유 — Specialist vs Generalist

- 28개를 한꺼번에 학습 = **제너럴리스트**(다 아는 두뇌).
- 하지만 에이전트마다 역할이 다름(디자이너·연구·운영·인스타…) → **각자 다른 전문 두뇌**가 필요.
  - 코더 두뇌 = 코딩 지식만 / 디자이너 = 디자인만 / 사업 담당 = 사업만.
- 그래서 지식을 카테고리로 나눠 **에이전트별 특화 모델**을 따로 학습·연결한다.

> 🌐 **커뮤니티 지식 네트워크:** 처음엔 한 사람의 지식 → 나중엔 군체처럼 **여러 전문가(주식·농업·요리…)의 검증된 지식**이 모여
> 우리 커뮤니티만 가진 차별화된 인공지능 모델로 진화. (밖에 공개하지 않는 자산)

## 🧠 머신러닝 3대 학습 패러다임 (복습)
| 패러다임 | 방식 | 예시 |
| --- | --- | --- |
| **Supervised (지도)** | 정답을 주입 (SFT) | "이건 커피야" × N |
| **Unsupervised (비지도)** | 스스로 패턴 찾아 분류 | 사진 100장 → 컵/종이 자동 구분 |
| **Reinforcement (강화)** | 보상(+)/벌점(−) 피드백 | 맞으면 +1, 틀리면 −1 |

> **에이전트는 많아질수록 멍청해진다 — 답은 '지식 공유'다.** 공유 게시판(MetaGPT)→공유 환경(AgentVerse)→
