# 🗄️ 성숙한 RAG 파일링 시스템 설계도 (RAGAS-주도)

> **한 줄 정의:** 여러 RAG 레시피(하이브리드·맥락보강·그래프·Self/Corrective·에이전트)를 단계별로 합치고, **RAGAS 평가를 시스템의 심장에 둔** 베테랑 사서급 검색·생성 아키텍처.
> **설계 철학:** *"측정되지 않는 검색은 미숙한 검색이다. 파이프라인이 아니라 평가 루프가 시스템의 본체다."*
> 관련: [RAG](./rag.md) · [Self-RAG](./self-rag.md) · [Graph RAG](./graph-rag.md) · [Agentic RAG](./agentic-rag.md) · [데이터가 적어도 되는 이유](./why-finetuning-needs-little-data.md)

---

## 0. 두 개의 루프 (이 설계의 핵심)

```
        ┌──────────────── 런타임 루프 (질의→답변) ────────────────┐
사용자 → 라우팅 → 검색전 → 검색 → 통합 → 생성(인용) → 자가검증 → 답변
        └───────────────────────────┬────────────────────────────┘
                                     │ 모든 단계 로그·인용 적재
                                     ▼
        ┌──────────────── 평가 루프 (RAGAS) ──────────────────────┐
   골든셋 ↔ 오프라인 평가(CI 게이트) ↔ 온라인 모니터링 ↔ 실패수집 → 개선
        └─────────────────────────────────────────────────────────┘
```

> 대부분의 RAG가 위쪽(런타임)만 만들고 끝낸다. **성숙함은 아래쪽(평가 루프)이 위쪽을 끊임없이 교정하는 데서 나온다.**

## 1. 전체 아키텍처

```
[수집/인덱싱 파이프라인]                         [질의 파이프라인]
원본 문서                                         사용자 질의
  │ ① 시맨틱 청킹(명제+슬라이딩윈도우)              │ ⑤ 라우팅(분류·복잡도)
  │ ② 맥락 보강(청크별 컨텍스트 헤더)               │ ⑥ 쿼리 재작성·분해·HyDE
  │ ③ 멀티 인덱싱                                   │ ⑦ 하이브리드 검색(Dense+BM25)
  │    ├ Dense(pgvector)                            │ ⑧ 재랭킹(크로스인코더)
  │    ├ Sparse(BM25)                               │ ⑨ 통합(필터·중복·압축)
  │    └ Graph(엔티티·관계, 커뮤니티요약)           │ ⑩ 생성(근거인용 강제)
  │ ④ 메타데이터·출처 태깅                          │ ⑪ 자가검증(Self/CRAG)
  ▼                                                 ▼
[저장소: Vector + BM25 + Graph + 원문]  ←─────────  [관측·평가 로그]
                                                          │
                                                          ▼
                                               [RAGAS 평가 하니스]
```

## 2. 단계별 레시피 합성 (무엇을 어디에 섞나)

| # | 단계 | 채택 레시피 | 왜 |
| --- | --- | --- | --- |
| ① | **청킹** | 시맨틱 청킹(명제 변환 + 5문단 슬라이딩윈도우) [MedGraphRAG] | 고정 글자수 분할의 맥락 손실 방지 |
| ② | **맥락 보강** | **Contextual Retrieval**(청크마다 "이 청크는 ○○문서의 ○○부분" 한 줄 prepend 후 임베딩) | 검색 실패율 대폭↓, 고아 청크 방지 |
| ③ | **인덱싱** | Dense(임베딩) + Sparse(BM25) + Graph 3중 | 의미·키워드·관계를 모두 커버 |
| ④ | **출처 태깅** | 내재적 인용(provenance) [MedGraphRAG] | 감사가능성=신뢰. 모든 청크에 source_id |
| ⑤ | **라우팅** | 질의 분류(단순/복합/관계형) → 검색 깊이 결정 | "안녕"에 그래프 검색 X |
| ⑥ | **쿼리 변환** | 재작성 + 멀티홉 분해 + **HyDE**(가상답변으로 검색) | 두루뭉술한 질의 정밀화 |
| ⑦ | **검색** | **하이브리드**(Dense + BM25, RRF로 융합) | 단어·뜻 약점 상호 보완 |
| ⑧ | **재랭킹** | 크로스인코더 리랭커(top-20 → top-5) | 1차 "빠르게 대충" → 2차 "느리게 정확" |
| ⑨ | **통합** | 관련성 필터 + 중복제거 + 컨텍스트 압축 | lost-in-the-middle 방지 |
| ⑩ | **생성** | 근거 인용 강제 + 무근거 시 폴백 | "출처 못 대면 단정 금지" |
| ⑪ | **자가검증** | **Self-RAG**(검색 필요여부 판단) + **CRAG**(검색 부실 시 재검색/웹 폴백) | 환각·엉뚱검색 교정 |
| ⑫ | **복잡 질의** | **Agentic RAG**(검색⇄추론 반복) [Survey] | "왜 X인데 Y?" 류 다단계 추론 |

> **레시피 선택 매트릭스 (과설계 방지)**
> | 질의 유형 | 쓰는 것 | 안 쓰는 것 |
> |---|---|---|
> | 단순 사실("A의 정의?") | 하이브리드+재랭킹 | 그래프·에이전트 |
> | 다출처 종합("전체 주제는?") | **Graph(커뮤니티 요약)** | — |
> | 멀티홉("A와 B의 관계가 C에 미친 영향?") | **Agentic(검색⇄추론)** + Graph | — |
> | 최신성 필요 | **CRAG**(웹 폴백) | — |
> | 안전·규제 도메인 | **MedGraphRAG**(3계층+인용) | — |

## 3. ❤️ RAGAS 평가 하니스 (시스템의 본체)

### 3.1 핵심 지표 4종
| 지표 | 측정 | 무엇을 잡나 |
| --- | --- | --- |
| **Faithfulness(충실도)** | 답변이 검색된 근거에서만 나왔나 | **환각** |
| **Answer Relevancy(답변 관련성)** | 답이 질문에 맞나 | 동문서답 |
| **Context Precision(맥락 정밀도)** | 가져온 청크가 관련 있나 (순위 반영) | **검색 노이즈** |
| **Context Recall(맥락 재현율)** | 필요한 근거를 다 가져왔나 | **검색 누락** |

> 보조: Answer Correctness(정답 대비), Context Entity Recall, Noise Sensitivity, (에이전트형) Tool-call Accuracy.

### 3.2 골든 테스트셋 (없으면 시스템도 없다)
- **구성:** 질문 + 정답(ground truth) + 근거 청크. 도메인 대표 질의 **최소 50~200개**.
- **다양성:** 단순·멀티홉·관계형·최신성·"자료에 없음(거절)"·적대적 질의를 골고루.
- **생성:** 문서에서 AI로 합성 후 사람이 검수(RAGAS의 testset generation 활용 가능).
- **버전관리:** 골든셋을 git으로. 문서 코퍼스 변경 시 함께 갱신.

### 3.3 두 층위 평가
```
[오프라인]  코드/프롬프트/인덱스 변경 시 → 골든셋으로 RAGAS 일괄 → CI 게이트
[온라인]    실사용 트래픽 샘플링 → 충실도·인용일치 모니터링 → 회귀 경보
```

### 3.4 CI 게이트 (회귀 차단)
```yaml
# rag-eval-gate (PR마다 실행)
thresholds:
  faithfulness:        ">= 0.90"   # 환각은 가장 엄격
  answer_relevancy:    ">= 0.85"
  context_precision:   ">= 0.80"
  context_recall:      ">= 0.85"
on_fail: block_merge            # 기준 미달 시 머지 차단
report: diff_vs_main           # main 대비 지표 증감 표로
```
> ⚠️ **단일 점수가 아니라 main 대비 델타로 본다.** "절대 0.87"보다 "어제 0.91→오늘 0.87 하락"이 더 중요한 신호.

### 3.5 평가 → 개선 폐루프 (지표별 처방)
| 떨어진 지표 | 1차 원인 | 처방 |
| --- | --- | --- |
| Context Recall ↓ | 검색이 근거를 놓침 | 청킹 크기·하이브리드 가중치·top-k ↑, 쿼리 분해 |
| Context Precision ↓ | 노이즈 많음 | 재랭커 강화, 필터 임계 ↑, 압축 |
| Faithfulness ↓ | 모델이 지어냄 | 인용 강제, 무근거 폴백, 온도 ↓, 프롬프트 가드 |
| Answer Relevancy ↓ | 질의 이해 실패 | 쿼리 재작성·라우팅 개선 |

## 4. 권장 기술 스택

| 레이어 | 선택 | 비고 |
| --- | --- | --- |
| 벡터 인덱스 | **pgvector**(PostgreSQL 확장) | 별도 DB 없이 시작, 운영 단순 |
| 키워드 | PostgreSQL FTS / OpenSearch(BM25) | 하이브리드의 한 축 |
| 그래프 | Neo4j / Apache AGE | GraphRAG 3계층 |
| 임베딩 | 도메인·언어 특화 모델(한국어면 bge-m3/KURE류) | 코퍼스 언어에 맞춰 |
| 리랭커 | 크로스인코더(Cohere Rerank류 또는 오픈) | top-k 재정렬 |
| 융합 | RRF(Reciprocal Rank Fusion) | dense+sparse 점수 결합 |
| 평가 | **RAGAS** + 골든셋 + CI | 시스템의 본체 |
| 관측 | 검색·인용·지연·토큰 로깅(민감정보 마스킹) | 온라인 평가 기반 |

## 5. 구축 단계 (점진적, 평가 먼저)

| 단계 | 내용 | 게이트 |
| --- | --- | --- |
| **P0** | 골든셋 50개 + RAGAS 셋업 + naive RAG 베이스라인 측정 | *평가부터 만든다* |
| **P1** | 하이브리드 검색 + 재랭킹 + 인용 | Recall·Precision ↑ 확인 |
| **P2** | 맥락 보강 청킹 + 라우팅 + 쿼리 변환 | Faithfulness ↑ |
| **P3** | Self-RAG/CRAG 자가검증 + 그래프 | 멀티홉·최신성 질의 통과 |
| **P4** | Agentic 검색⇄추론 + 온라인 모니터링 | 회귀 경보 가동 |

> **반드시 P0(평가)부터.** 베이스라인 숫자 없이 P1~P4를 쌓으면 "좋아진 것 같다"만 남는다.

---

## 6. 실패 모드 플레이북 (3대 함정)

| 증상 | 진단 | 조치 |
| --- | --- | --- |
| 답은 그럴듯한데 출처와 어긋남 | Faithfulness 낮음 | 인용 강제 + 무근거 폴백 + 온도↓ |
| 엉뚱한 청크를 가져옴 | Precision 낮음 | 재랭커·필터·압축, 청킹 재설계 |
| 맞는 근거가 코퍼스에 있는데 못 찾음 | Recall 낮음 | 하이브리드 가중치·HyDE·멀티홉 분해 |

---

## 7. 가드레일 (안전·신뢰)
- **무근거 단정 금지** → "자료에 없음/확인 필요" 폴백.
- **모든 사실 주장에 인용** (source_id 역추적 가능).
- **PII·민감정보** 로그 마스킹, 코퍼스 접근통제.
- **적대적 질의**(프롬프트 인젝션) 골든셋에 포함해 정기 점검.

---

## 8. ✅ 성숙도 체크리스트
- [ ] 골든 테스트셋이 있고 git으로 버전관리되나
- [ ] RAGAS 4지표가 CI 게이트로 걸려 있나 (머지 차단)
- [ ] main 대비 **델타**로 회귀를 보나
- [ ] 검색이 하이브리드 + 재랭킹인가
- [ ] 청크에 맥락 헤더 + 출처가 붙나
- [ ] 무근거 시 폴백/거절이 동작하나
- [ ] 단순/복합 질의를 라우팅으로 분기하나
- [ ] 온라인 트래픽 일부를 모니터링하나

> **한 줄 결론:** 레시피를 화려하게 섞는 게 성숙이 아니다. **골든셋 + RAGAS 게이트로 매 변경을 측정·교정하는 폐루프**가 있을 때, 비로소 베테랑 사서다.
