# 에이전트 자율성 & 가드레일

**한 줄 정의:** 에이전트에 자율성을 얼마나 줄지 정하고, 위험 행동을 코드로 막는(가드레일) 제어 설계.

## 자율성 vs 자동
- 자율성을 과하게 주면(넷플릭스식) → **잘하는 사람만 모였을 때만** 작동. 대부분은 놀거나 책임감↓.
- AI 에이전트는 아직 사람만큼 똑똑하지 않음 + 도구(결제·업로드·API)가 늘면 복잡도 폭발.
- → 자율성을 줄지/자동으로 할지 정하고 도구를 **촘촘히 시스템화**해야 함.

## 가드레일 (Policy/Hook)
- 위험 명령(`rm`, `delete`, `shutdown`…)을 검증 함수로 자동 차단.
- 예: `policy.deny("run_command", when=check_command_danger)` + `policy.allow_all()`.
- = **Human-in-the-Loop**(실행을 허가하십니까?) 보안 패턴의 코드화.

## 왜 중요한가
- 권한을 통째로 주면 대참사: 무한 루프로 영상 만들다 수백만 원 청구된 사례.
- → **세분화된 권한 설정**이 핵심. "100만 원 이상 결제 시 사장 승인 대기" 같은 비즈니스 로직도 코드로.
